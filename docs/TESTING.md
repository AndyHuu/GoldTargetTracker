# 游戏内测试

在备份插件与存档后安装，脱战执行 `/console scriptErrors 1` 和 `/reload`。不要把以下待执行步骤当作全部已经通过。

1. 检查固定名称金币进度条、原有目标、角色快照、历史和名单是否保留。
2. `/gtt` 与小地图图标能开关面板。右击空白和进度条，检查三个开关与设置入口。
3. 锁定后不能拖动但可以右键解锁；隐藏图标后可用命令打开面板并恢复。
4. 设置页四项导航正常。预设目标切换立即更新输入框和百分比，修改目标不庆祝。
5. 目标以下百分比不得提前到 100.00%。实际赚金币跨线时主面板隐藏，庆祝保持至手动关闭。
6. 战前开/关、战斗隐藏开关开/关、战斗中命令、脱战恢复分别验证。
7. 自动使用页文字应清晰，名单可滚动到最后一项，名称和移除对应正确，长名称悬停可读。
8. 用可丢弃的低价值物品检查新增/堆叠增加与移动/拆分/合并。以实际数量核对，不把“已尝试”当作成功。
9. 检查冷却、锁定、邮件/银行/交易和战斗暂停；队列在重载保留、正常退出后清空。
10. 有正收益时记录账号总金币、今日收益、预计时间，正常切角色后对照，不能因退出临时零值改变快照。
11. 今日净收益非正时应说明暂无正收益，零时长时说明正在采集；条件满足后恢复预测。
12. 正式存档上的重置测试先只点取消；实际清空仅在可丢弃测试数据上验证。

报告问题时提供版本、步骤、预期与实际、错误原文。诊断输出和截图可能包含角色名称及余额，公开前先脱敏。


## rc8 金币来源验收（待游戏内执行）

新增功能验收先备份当前插件代码及本插件 SavedVariables。打开设置 → 金币来源，记录累计金额，操作后等待约两秒对照差额。以下用自己的实际金额核对，不需清空正式存档。

1. 检查四页导航、主面板右键“设置”跳转、原有设置与历史保留。首次使用来源页应显示零收入及开始时间，已有金币不算收入。
2. 向商人出售一件低价值物品，来源只增加实际售价；再购买/修理，累计收入不减少。商人窗口开着时完成任务，奖励应归任务。
3. 完成金币世界任务，再完成普通任务，分别检查两类。只送物品的任务不直接计金币；之后卖掉物品才算售卖。
4. 拾取怪物/宝箱金币，核对金银铜；切换地图、关闭所有面板后获取金币，仍应记录。
5. 在有现成成交款时，先检查尚未领取不计收入；领取后只增加拍卖到账，按实际收款核对，勿再加一次邮件收入。批量收取含普通汇款的邮件时两类应分别增加。
6. 与可信玩家交易少量金币并完成，检查交易收入；取消交易不增加。自己小号邮件、玩家交易按既定口径仍累计。
7. 从战团银行、公会银行及可存钱的个人银行分别取少量金币，再存回，来源累计不变。银行窗口开着时收到任务奖励仍应计任务；其他成员取公会钱不能影响本人收入。
8. 收款后立刻正常退出或重载，再登录/换角色，收入只保留一次。关闭/隐藏主面板不影响记账。
9. 调整游戏缩放和设置画布，检查八行、金额、占比、空状态可见且不越界。
10. “重置今日统计”应保留来源累计。正式数据上“重置所有”只验证弹窗和取消；清空与开始时间更新只在已备份的可丢弃测试存档上验证。

若某笔收入归入其他，请记录操作、金额、发生时机和Lua错误；不要公开真实存档。回购栏已满的重复物品、过迟的来源事件及合并收支属于需重点复核的边界。


## rc9 设置界面验收（待游戏内执行）

1. 重载后确认导航依次为“总览、金币来源、自动使用、设置”。总览只保留目标进度、收益表现、预测和趋势，角色资产不再出现在这里。
2. 对比自动使用名单，检查其余页面的正文、说明、按钮、输入框与图表日期均清晰可读。缩小设置画布时字体不能跟着缩小；内容通过右侧滚动条查看。
3. 金币来源向下滚动，确认“累计到账收入 → 来源构成 → 统计说明 → 角色资产”的顺序。来源金额、占比和角色余额应与更新前一致。
4. 资产超过5个角色时展开全部，确认最末角色可滚动到；滚动到底部后收起列表，不能留下大块空白或出现第二条资产列表滚动条。长角色名可悬停读取。
5. 调整画布宽度，趋势点和连线应留在图表内部，仍有7个日期的数据点；窄窗口仅精简日期文字，悬停仍能查看数据。
6. 核对较长的目标预测、自定义名称、开始时间与设置说明不越出分区。检查500万/700万预设、自定义目标、名称、战斗隐藏与重置取消仍正常。

此次仅改设置界面布局，不重置历史、累计来源或角色数据。真实画布、字体渲染和游戏UI缩放仍需按上述步骤验收。


## rc10 紧凑间距验收

重载后对比三个页面：字号保持14号、行距更紧凑；缩窄设置窗口，说明文字与按钮/复选框不能重叠。金币来源滚动到底部并展开/收起资产，确认最末行可见且不留多余空白。


## rc11 四页统一紧凑验收

1. 重载后依次查看四页：字号不变，自动使用名单和顶部也更紧凑；检查添加、开关、清空及最后一行移除。
2. 设置页500万/700万、两种预设名称和两个重置按钮各自并排，仍可点击；说明不应被裁切。
3. 在正常和较窄画布切换来源页：金额/占比由同行变为换行，数字不变；有收入后不再保留空状态提示空间。
4. 总览预测较长时应自动换行并推开后续内容；切换角色、展开收起资产后，分区连续排列，页尾不留固定大块空白。

正式存档上的重置只验证弹窗及取消。紧凑排布的实际点击区域与游戏缩放仍需登录确认。


## rc12 首次余额与固定名称验收

1. 重启客户端，插件列表、设置标题、总览标题、小地图提示应显示“金币进度条”；设置页不再有名称编辑，来源页不再有统计说明分区。
2. 记录累计收入，正常切换角色/重载，只加载已有金币不应增加来源收入。再实际获得金币，确认只增加新到账部分。
3. 初始零余额/慢加载时，无来源的首次正余额仅作基准；初始校准期内有明确任务/拾取等证据的真实奖励仍可记录。校准后正常收入继续累计。
4. 进出副本/切换地图与正常退出时，钱包读数变化不能凭空增加其他收入；重置所有仅在可丢弃测试数据上验证，重置后真实收入应继续记录。
5. 旧的其他收入不会自动变小；缺少逐笔证据，不能按现有角色余额倒推扣除。不要为了测试直接清空正式数据。
