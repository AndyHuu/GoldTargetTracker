# 金币进度条（GoldTargetTracker）

魔兽世界正式服金币目标追踪插件。当前版本 **2.3.0-rc1**，TOC Interface **120107 / 120105 / 120100**。

## 功能

- 账号总金币 = 当前角色实时金币 + 其他角色最近快照 + 战团银行共享金币（只计一次）。
- 横向主面板；`/gtt` 或 `/goldtracker` 开关；可拖动并记忆位置。
- 百分比保留两位小数并向下截取，未达标最高 99.99%。
- 主面板右键菜单：战斗中隐藏、锁定窗口、小地图图标，底部直达设置页。
- 固定显示名称为“金币进度条”；已移除名称修改及金币来源的统计说明分区。
- 设置分为总览、金币来源、自动使用、专业循环、设置五页；500 万、700 万和自定义目标即时同步；预设按钮以500万/700万简写，并排显示。
- 累计金币来源：商人售卖、世界任务、其他任务、拾取、拍卖到账、邮件、玩家交易及其他收入；银行取款排除。
- 总览集中展示目标进度、收益表现、目标预测与七日趋势；角色资产移至金币来源底部，支持展开全部。
- 实际跨线达标时隐藏主面板，庆祝提示保留至手动关闭；修改目标本身不触发庆祝。
- 自动使用名单最多 20 项，亮色滚动列表；仅明确新增数量入队，移动/拆并保持保守。
- 队列战斗暂停、冷却/锁定重试；重载保留，正常登出清空。
- `/gtt debug` 提供本地诊断；退出阶段保留最近观测数据，避免临时零值覆盖角色快照。

- 专业循环已整合 AndyCraftCycle：回收材料、制造配方、分解物品各有可增删列表，按角色保存；沿用“安迪循环”宏。详见 [专业循环说明](docs/PROFESSION_CYCLE.md)。

## 安装与更新

1. 更新前退出游戏，独立备份现有插件及对应 SavedVariables。
2. 把仓库中的 `GoldTargetTracker` 文件夹放入游戏的 `_retail_/Interface/AddOns/`。
3. 文件夹内应直接包含 `GoldTargetTracker.toc`、`IncomeSources.lua`、`CycleLists.lua`、`ProfessionCycle.lua`、`CycleSettings.lua` 和 `GoldTargetTracker.lua`，不要多套一层目录。
4. 登录后检查数据仍在；游戏运行中更新代码后，脱战输入 `/reload` 加载。

存档变量是 `GoldTargetTrackerData` 与 `GoldTargetTrackerBackup`。它们位于同一个 SavedVariables 文件，Backup 是独立表快照，**不是独立磁盘备份**。游戏运行时不要覆盖 SavedVariables。专业循环另外使用角色独立变量 `GoldTargetTrackerCycleData`，不修改金币历史。旧 AndyCraftCycle 可停用；已有“安迪循环”宏继续使用。

## 已知边界

- 其他角色是最近观测快照，不是实时查询；记录错误的历史角色余额应通过实际登录刷新。
- 缺失日收益显示 0，总金币沿用前值；日快照不是逐笔交易流水。
- 今日速度预测沿用小时快照近似，包含离线间隔；无正收益或零时长会说明原因，不伪造预测。
- 无消耗证据连续三次尝试后保留并暂停队首，脱战/交互关闭再试，可能暂时阻挡后续任务。
- 自动使用受实际客户端保护机制限制，不绕过硬件操作或受保护 API。
- 设置页正文至少14号，与自动使用一致；原有页面采用24像素列表/控件节奏和4像素分区间隔，专业循环条目采用28像素行高，自动使用页同步收紧；分区按内容高度排列，总览、金币来源、专业循环、设置使用纵向滚动，不再通过缩小整页字体适配窗口。图表宽度变化时重排点位，窄窗口精简日期刻度。
- 来源从首次启用功能开始累计，约 1–2 秒刷新；进入世界建立钱包基准，离开世界停止采样。初始化半秒内的未知增量不入账；初始钱包为零或不可读时，首个无来源正余额只建立基准，明确来源的奖励仍可确认入账。原有汇总无法逐笔回溯，升级不自动扣减旧收入；不追溯旧历史。只记录已观测的正向金币变化，不是扣除支出后的利润。邮件/交易转钱会再次累计；拍卖按实际领款（含退回押金）统计。
- 来源证据需在余额变化前后约一秒内匹配；延迟、接口不可用或来源不明时可能归入其他收入。多个收支合并为一次余额事件时，无法保证还原每笔收入。
- 商人售卖需背包减少与新增回购记录相符；回购栏满且连续出售完全相同的物品导致记录无法区分时，保守归入其他收入。
